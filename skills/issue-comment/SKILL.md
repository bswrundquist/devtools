# Issue Comment

Write one comment that sounds like a knowledgeable teammate: clear, direct, human, and complete enough for someone to understand the update and take the next step without reading the conversation.

## Ground the comment

Use the supplied context and relevant issue details available through read-only tools. Distinguish completed work from proposed work and verified findings from assumptions. Never invent facts, validation results, owners, deadlines, URLs, issue numbers, evidence, or references. Flag consequential unknowns rather than guessing.

## Write the comment

- Lead with the main update, finding, decision, or request.
- Include the context needed to understand why it matters. Avoid repeating information already clear from the issue unless needed to understand the comment.
- State what changed, the current status, and any next step or blocker when relevant.
- For technical changes, include relevant validation results and meaningful limitations. Never imply that an unperformed check passed.
- If action is needed, make the request explicit. Include an owner or deadline only when known.
- Use plain language, natural sentences, and active voice. Do not use em dashes, canned introductions, filler, hype, or unnecessary formality.
- Match detail to the update. A simple update may need only two sentences. A complex finding may need short paragraphs and bullets. Do not impose a fixed template.

## Links and references

- Include relevant links when available, such as related issues, pull requests, commits, documentation, logs, or artifacts.
- Use descriptive link text or the platform's native issue references and formatting supported by the destination.
- Place a single link near the statement it supports. Group several references into a short list when easier to scan.
- Link to supporting details instead of copying lengthy logs or background material.
- Verify links when practical. Do not treat an inaccessible link as verified.

## Final check and output

Check that the comment is accurate, understandable on its own, consistent with the available evidence, and free of unnecessary detail or sensitive information. Ensure completed and proposed work, validation results, limitations, requests, and consequential unknowns are represented accurately when relevant.

Return exactly one ready-to-post comment using formatting supported by the destination. Do not add explanations around the draft. Drafting alone does not authorize posting; do not submit or publish the comment without explicit authorization.
